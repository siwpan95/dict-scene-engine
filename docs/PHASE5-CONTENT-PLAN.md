## 0. 结论卡（TL;DR）

- **现状**：18 包 / 268 场景 / 57k 字 / 58 结局；4 mode（normal/battle/trade/diary）+ 时间循环（@loop + reset keep）；已验证引擎能撑复杂分支主线、模式扩展、风格差异短篇池、跨包联动、年代跃迁长线。
- **最大缺口**：**中篇仅 1 个标杆**（《江畔·县志》20 场景 / 5.2k 字）；短篇 7 个偏多，且其中 4 个题材同质（市井民俗情感，AI 产线生成）。
- **Phase 5 主张**：以「**补中篇为骨干 + DLC 平行加法 + 1 条群像网状长线 + 题材差异化短篇**」为主轴，**不盲目冲字数**，优先补结构缺口而非体量。
- **量化目标**（保守档）：场景 268 → ~360、字数 57k → ~78k、结局 58 → ~78、内容包 18 → ~26、**中篇数 1 → 6**。
- **引擎改动**：优先零改动（内容层用 flags/items/数值 + goto 表达）；**仅 1 项可选增强**（dialogue/谈判 mode）在群像长线落地时启用，否则用 flags+goto 模拟。

> 全哥拍板项见 §12。本文档为规划草案，方向确认后再产出 §7 各项的详细设计稿（仿 M14-HUSHI-DESIGN.md 体例）。

## 1. 项目运作机制速览（规划锚点）

> 已读 README.md / CONTENT-EXPANSION-PLAN.md / NARRATIVE-LEDGER.md / M14-HUSHI-DESIGN.md 核实。此处只列与规划直接相关的约束。

- **场景字典 schema**：`text`/`title`/`choice.text` 均支持 `{path}` 插值；`onEnter` effects；`if` 条件（`new Function` 求值，玩家输入不进此处）；`goto` / `@restart`（全量重置）/ `@loop:<sceneId>`（保留域部分重置）。
- **4 种 mode**：`normal`（默认）/ `battle`（战斗，combat.js）/ `trade`（经营，trade.js）/ `diary`（日记回溯只读，diary.js）。
- **结构范式**：branch-and-bottleneck（古堡主线）/ hub-and-spoke（侦探两案、商队、江畔）/ 时间循环（子夜集）/ 年代跃迁五幕（藏晖室札记）。
- **扩展机制**：`cordis.yml` 声明式组装；跨包彩蛋（caravan↔town 双向）；lint 校验（悬空/可达/账本/契约/数值字段）；e2e + traverse + coverage 三层测试门（58 结局全覆盖）。
- **新增第四/五种 mode 要改 4 处**（缺一不可，否则 lint/traverse 判不可达）：① 插件 `ctx.on('scene/mode')` 接管；② `scripts/lint-content.mjs` 的 `MODE_EDGES`；③ `tests/traverse.mjs` 的 `MODE_NEXT`（**与 lint 是两份独立的表，最易漏**）；④ `cordis.yml` 注册 + `state.initial` 字段声明。
- **安全红线**：`content/*.js` 是可执行 ESM 模块（`import()` 即执行顶层代码）；新内容包只装可信来源。

## 2. 现状基线与缺口诊断

### 2.1 篇幅分布（实测，按内容包）

| 分级 | 场景/字数区间 | 现有内容包 | 数量 |
|---|---|---|---|
| 短篇 | 8–15 场景 / 1.5–2.5k 字 | 千灯 8 / 面摊 9 / 萤火巷 8 / 皮影 8（市井民俗情感×4，AI 产线）+ 武侠《刀客》16 / 科幻《空间站疑云》12 / 恐怖《古宅惊魂》14（风格短篇×3） | **7** |
| 偏短中篇 | 12–19 场景 / 3–3.5k 字 | 东市经营 12 / 驿路 13 / 子夜集 19 / 荒漠商队 19 | 4 |
| **中篇** | 15–25 场景 / 3.5–5.5k 字 | **《江畔·县志》20 场景 / 5.2k 字** | **1（唯一标杆）** |
| 长线/主线 | 25+ 场景 / 5k+ 字 | 古堡主线+地下层 48 / 星港两案 29 / 胡适五幕 33 | 3 |

**诊断**：中篇是**结构性缺口**（1 个 vs 短篇 7、长线 3）；短篇池 4 个题材同质（均为"夜宿一地、撞见未了之事"的市井民俗情感，AI 产线生成）。

### 2.2 题材缺口（对照 CONTENT-EXPANSION-PLAN §15.2 + 2026 调研）

- **已覆盖**：古堡幻想 / 侦探推理×2 / 商队贸易 / 城镇经营 / 武侠 / 科幻 / 恐怖 / 时间循环 / 情感×5（驿路+4市井）/ 历史推理 / 年代传记。
- **缺/弱**：末日生存 / 黑色幽默 / 克苏鲁心理恐怖 / 校园青春 / 职场社会 / 硬科幻 / **群像多视角** / **密室本格** / 战争历史 / 民国都市生活 / 仙侠江湖门派。
- **2026 验证品类**（结构可借鉴，见 §4）：哀鸿·城破十日记（记篇+忆篇双篇章/史实考据）、景安区奇案（公平推理/12结局非线性）、少年宋慈（古代法医）、大喜之日（中式恐怖/多周目）。

### 2.3 机制缺口

- **已有 mode**：normal / battle / trade / diary + 时间循环（@loop + reset keep）。
- **未用/可选**：对话谈判 mode、解谜机关 mode、地图探索 mode、关系两轴数值系统（现 karma 为单轴）、随机/变体文本（E3 自 M0 起搁置）、多角色切换。
- **可零改动表达**：关系两轴（数值字段，仿 toleration/independence 双轴）/ 解谜机关（if/do + items）/ 多视角（flags + goto 模拟）/ 双篇章切分（hushi 已示范五幕）/ 网状多结局（branch + bottleneck + 多入口）。

## 6. 分项详细规划（设计意图级，非填充稿）

> 每项给：一句话立意 / 结构骨架 / 机制映射 / 规模 / 与现有内容的衔接点 / 验收。文本在方向确认后产出（仿 M14-HUSHI-DESIGN.md 体例单开设计稿）。

### 6.1 新主线（2 候选）

#### A1《渡口纪年》——跨世界观群像长线（P0）
- **立意**：古堡/商道/民国/江畔四个既有世界在一处渡口交汇，一甲子间来往过客各执一桩未了之事。对标 428（严格因果链）/ 底特律（多角色交织）的**网状多视角**。
- **结构**：key nodes（渡口四时：春渡/夏汛/秋枯/冬冰，众见）+ 多 POV 切换（每位角色一段支线，汇入渡口节点）。
- **机制映射**：`flags.pov.*` 标记当前视角角色；goto 切换视角；每位角色线用独立 flags 命名空间（仿 case.*/crew.*）。**可选 dialogue mode** 若启用则谈判/对话场景接管（见 §8-E6）。
- **规模**：40+ 场景 / 9k+ 字 / 6–8 结局。
- **衔接点**：渡口可承接古堡商人（demo）、商队（caravan）、江畔画工（river）、胡适归国渡轮（hushi.p3）的"过路"彩蛋。
- **验收**：每 POV 至少 1 结局；多 POV 顺序不影响各自通关；跨 POV 信息交织（A 视角线索在 B 视角被读取）≥3 处。

#### A2《长安·西市》——历史都市生活长线（P1）
- **立意**：唐代西市胡商/市井/官府/寺观多 hub，玩家一介行商周旋其间。对标历史品类验证（《山河旅探》《少年宋慈》同频中文市场）。
- **结构**：多 hub（西市/常乐坊/胜业坊/太极宫前）+ quest structure（内容附着于地点）。
- **机制映射**：复用 trade 数值（金币/库存）+ 多 hub 重访（仿 village/case.board）；零引擎改动。
- **规模**：40+ 场景 / 9k+ 字 / 7 结局。
- **衔接点**：可与商队 caravan（丝路来路）、东市 town（同名经营）做跨包彩蛋。
- **验收**：4 hub 皆可重访幂等；每 hub 至少 1 支线结局；总结局全可达。

### 6.2 DLC（4 候选，平行加法，不改本体结局）

> 铁律（依据④）：**本体在 DLC 前已完整**；DLC 是平行扩展，**不改本体结局意义**；游戏内清晰标注"DLC 是额外扩展"。以下均满足本体已完整前提。

#### D1 古堡前史 DLC《筑堡者》（P1）
- **立意**：古堡寻剑主线已完整（ending.sword 等 4 结局），DLC 回到建堡者年代，揭示诅咒起源。**前传，不影响本体**。
- **结构**：branch-bottleneck（建堡者三子分线 → 诅咒形成瓶颈）。
- **机制映射**：现有，零改动。
- **规模**：15–20 场景 / 3–4k 字 / 3 结局。
- **衔接点**：本体 `castle.library` 的 `flags.swordLore` 可在 DLC 末尾被"预言"，但本体不依赖 DLC。
- **验收**：本体结局在有无 DLC 下意义不变；DLC 独立通关。

#### D2 星港第二季 DLC《回声》（P1）
- **立意**：星港两案已完整，第二季新案件，沿用 hub-and-spoke + 知识标记。对标公平推理（依据③）。
- **结构**：案卷桌 hub + 6–8 spoke + 指认纠错（仿 river）。
- **机制映射**：`clues.echo.*` / `suspectLevel` 复用。
- **规模**：18–22 场景 / 4k 字 / 3 结局。
- **验收**：线索全在前期对话（公平推理）；错指认有代价可纠错。

#### D3 胡适 DLC《藏晖室·余墨》（P2）
- **立意**：胡适五幕已完整（7 结局），DLC 补 1920s 白话文运动 / 1930s 驻美前夜切片，复用 diary mode。
- **结构**：两片切片（1921《尝试集》/1937 庐山）+ diary 回溯关卡。
- **机制映射**：diary mode 复用，零新 mode。
- **规模**：15–20 场景 / 4k 字 / 3 结局。
- **衔接点**：本地史料 `G:\local\hushi_twrj` 1920s/1930s 卷可引用（OCR 卷遵循既有引用政策）。
- **验收**：diary 只读红线不破（重读不回写状态）。

#### D4 子夜集 DLC《第二夜》（P2）
- **立意**：子夜集已完整（4 结局），DLC 另一个循环夜，复用 @loop + 保留域。
- **结构**：循环壳 + 4–5 spoke + 破局。
- **机制映射**：`@loop:` + `loopKeep` 复用，零改动。
- **规模**：12–16 场景 / 3k 字 / 3 结局。
- **验收**：每轮必变约束；单轮不可达真相。

### 6.3 长线（2 候选）

#### L1《同一夜·十二时辰》——群像多视角网状（P0）
- **立意**：一座城一夜之间六个角色各自行动，子丑寅卯……十二时辰切换视角，每人持一碎片，拼出同一事件。对标 428（严格因果）/ 底特律（多 POV 交织）。
- **结构**：key nodes（每时辰节点众见）+ 6 POV 支线 + 时序锁（丑时事件需子时已发生）。
- **机制映射**：`flags.pov` + `flags.hour` + goto 视角切换；时序锁用 `if: flags.hour >= N`。**内容层零改动**。
- **规模**：28–35 场景 / 7k 字 / 6 结局（每 POV 1 + 1 真相汇流）。
- **验收**：6 POV 各自可独立通关到 POV 结局；汇流真相结局需集齐 ≥4 POV 碎片；时序锁无死锁。

#### L2《城破·记与忆》——双篇章历史长线（P1）
- **立意**：对标《哀鸿》双篇章（依据②）。**记篇**=城破十日的残酷现在，**忆篇**=十年前的唯美过往，两篇对照收束。
- **结构**：记篇（gauntlet 生存线，资源管理）/ 忆篇（branch 情感线）/ 篇末汇流。
- **机制映射**：`flags.chap` 标记当前篇章；记篇用水量/天数数值（仿 horror 蜡烛资源管理），忆篇用关系 flag。
- **规模**：25–32 场景 / 6.5k 字 / 5 结局。
- **衔接点**：可承接江畔 river（同历史质感）与胡适 hushi（同史实质感）。
- **验收**：两篇各自可独立体验；汇流结局需两篇关键 flag 皆满足。

### 6.4 中篇（5 候选，重点补齐）★

> 这是 Phase 5 的**骨干**——把中篇从 1 个标杆扩到 6 个。

#### N1《雪庄·八客》——暴风雪山庄本格（P0）
- **立意**：风雪封山，八客困庄，一人暴毙，七人各怀秘密。中篇本格推理标杆，对标《景安区奇案》公平推理（依据③）。
- **结构**：hub（庄主厅）+ 7 spoke（七客房间/往事）+ 指认台。**指认可错、有代价、可纠错**（深化 river 模式）。
- **机制映射**：`clues.snow.*` + `snowEvidence` 计数 + 误导动机（2 人"像凶手"）。
- **规模**：18–22 场景 / 4.5k 字 / 5 结局（真凶/冤·甲/冤·乙/退堂/全员灭口）。
- **验收**：所有破案依据在前期对话（公平）；错指认走半失败挫败点可回查纠错。

#### N2《渡口·子丑》——同一夜多视角中篇（P0）
- **立意**：L1 的中篇版先行验证——同一夜两视角（子时/丑时），拼出真相。key nodes 结构（依据⑤）。
- **结构**：2 POV × 时辰节点众见 + 各自支线 + 汇流。
- **机制映射**：`flags.pov` + `flags.hour` + goto。
- **规模**：18–22 场景 / 4k 字 / 4 结局。
- **验收**：两视角各自可通关；汇流结局需两视角关键 flag。

#### N3《戍卒·家书》——双篇章历史中篇（P0）
- **立意**：L2 的中篇版先行验证——**记篇**=边塞戍卒当下（烽火/巡城/同袍），**忆篇**=家书往来（故乡/妻儿/期许）。双篇章对照（依据②）。
- **结构**：记篇 gauntlet + 忆篇 branch + 信物贯穿（一封家书跨篇）。
- **机制映射**：`flags.chap` + `items.letter` 跨篇信物 + 关系 flag。
- **规模**：18–22 场景 / 4.5k 字 / 4 结局。
- **验收**：信物在两篇皆被读取；两篇对照情感落点（残酷现在 vs 唯美追忆）。

#### N4《茶肆·三遇》——关系数值情感中篇（P1）
- **立意**：同一茶肆，三年三遇，关系随选择演进。补情感第一大类（依据①），但用**双轴数值**深化（仿 hushi toleration/independence）。
- **结构**：三幕（三年各一遇）+ 每幕 hub（茶肆）+ 关系分流。
- **机制映射**：`trust`（信任）/ `closeness`（亲近）双轴数值，仿 hushi 双轴分流结局。
- **规模**：16–20 场景 / 3.5k 字 / 4 结局。
- **验收**：双轴各自 ≥3 阈值档位影响对话；无死数值。

#### N5《机巧阁》——程序化解谜机关中篇（P1）
- **立意**：一阁机关连环，玩家以 if/do + items 解谜推进。验证"解谜可零改动内容层表达"。
- **结构**：hub（阁前）+ 机关链（每关一 item 钥匙 + 一 if 门槛）。
- **机制映射**：`items.gear.*` + `if: items.gearX >= 1` 门槛，纯内容层。
- **规模**：18–22 场景 / 4k 字 / 3 结局。
- **验收**：每机关有可观察后果（fail-forward，不卡死）；解谜逻辑无矛盾。

## 9. 验收标准（Phase 5 通用，沿用 §15.6）

1. 新线独立可通关（e2e 至少 1 条全路径 + 全结局可达）。
2. `lint:content` 0 错误 0 警告（含契约/数值字段/成就场景校验）。
3. `npm test` 全绿（e2e 558 + 新增）；traverse + coverage 双门不回归。
4. 若含新引擎语义（dialogue mode 等）：有专门断言覆盖，不破坏现有 @restart/save-load/@loop。
5. 中篇专属：关键选择≥6、情节密度 0.6–1.2、3–5 结局全可达、无假选择、无死变量。
6. DLC 专属：本体结局在有无 DLC 下意义不变；游戏内清晰标注"DLC 是平行扩展"。
7. 跨包联动≥1 处（彩蛋或共享 NPC/地点），向块茎网演进。
